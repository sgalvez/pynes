# v1.1.0 - Five-channel audio and emulation performance

Release date: 2026-11-14

Tag: `v1.1.0`

Compare: `v1.0.3...v1.1.0`

Status: Prepared in [PR #40](https://github.com/sgalvez/pynes/pull/40).
The date above is the planned publication date; the release is published only
when its validated version tag is pushed or the release workflow is dispatched.

## Summary

This release resumes development after
[v1.0.3, published on July 2, 2026](https://github.com/sgalvez/pynes/releases/tag/v1.0.3).
It delivers an NTSC five-channel APU pilot, scanline-based graphics, less
repeated CPU and rendering work, desktop frame diagnostics, and documentation
that explains the emulator from first principles.

The practical result is more complete sound generation and more processing
headroom in the tested scenes. Audio remains experimental and opt-in. The
emulator remains a pre-alpha NES implementation developed with AI assistance;
this release does not establish full game compatibility or exact hardware timing.

## Changelog Since v1.0.3

### Audio

- Replace the earlier four-channel oscillator with CPU-cycle-driven pulse 1,
  pulse 2, triangle, noise, and DMC units.
- Add DMC sample reads through the mapped CPU bus, looping, address wrap,
  nominal DMA stalls, status, and sample-end IRQs.
- Add pulse sweep behavior, channel envelopes and length counters, triangle
  linear-counter gating and held output, and both noise feedback modes.
- Route APU frame and DMC IRQ levels to the CPU, including interrupt-mask
  behavior exercised by generated test programs.
- Mix all five channels using nonlinear pulse/TND relationships and generate
  mono signed 16-bit PCM at 44,100 Hz by default.
- Defer synthesis until relevant register accesses, PCM consumption, or
  CPU-visible events. Advance channel timers and noise state in batches to
  reduce Python overhead while preserving the modeled timeline.
- Bound retained PCM and pending playback blocks to prevent an unlimited
  backlog. Clear playback queues on pause, reset, and shutdown.
- Provide WAV capture and a generated five-channel demo with individual channel
  selection, without requiring a proprietary ROM or audio device.

The previous floating-point oscillator edge correction and output shaping are
superseded by the new hardware-state model. Band-limited synthesis and complete
analog filtering remain pending; this release should not be understood as
retaining every smoothing feature described in the v1.0.2/v1.0.3 notes.

### Rendering And Timing

- Replace whole-frame snapshots in the normal execution path with scanline
  composition and event-based PPU advancement.
- Track scroll/address latches, fine scrolling, cartridge nametable mirroring,
  and palette state across rendering events.
- Compose 8x8 and 8x16 sprites with flips, priority, clipping, transparency,
  the eight-sprites-per-scanline limit, and approximate sprite-zero-hit timing.
- Advance PPU and optional APU clocks through CPU execution, OAM/DMC stalls,
  and interrupt service time.
- Reuse a packed RGB framebuffer and pygame surfaces, preserving RGB color
  ordering during presentation.
- Handle window resize, maximize, and restore without passing a destination
  surface of the wrong dimensions to pygame scaling. Preserve the image's
  aspect ratio with borders as needed.

### Cartridge Compatibility

- Read basic NES 2.0 headers for the existing NROM/MMC1/UxROM cores, including
  extended mapper IDs, submappers, ROM sizes, explicit RAM sizes, and timing.
- Support UxROM submapper 1 without bus conflicts and submapper 2 with the
  ROM/CPU AND operation applied before changing banks. Unspecified NES 2.0
  UxROM boards use conflicts; legacy iNES behavior is preserved.
- Expose only declared NES 2.0 PRG RAM and allocate the declared supported CHR
  RAM, with specific errors for unsupported layouts and hardware.
- Validate the reported local NES 2.0 UxROM file through startup, controller
  input, 420 headless frames, and PCM generation without modifying its bytes.
  Commercial ROM data and screenshots remain local and ignored by Git.

See [cartridge formats](../cartridge-formats.md) for the supported subset.

### Performance And Diagnostics

- Reduce overhead in the common CPU PRG read and opcode-fetch paths.
- Cache MMC1 bank calculations and background decoding using the relevant live
  mapper and graphics data.
- Reduce repeated sprite work and avoid rebuilding display buffers each frame.
- Add **F3** desktop statistics: FPS, emulation/audio/video work time, and frames
  exceeding the 16.7 ms work budget. Pacing waits are excluded from work time.
- Extend headless profiling to include APU synthesis and optional DMC stress.

The documented local water-stage workload improved from **46.84 to 61.88
headless frames/sec**, approximately **32% more throughput**, during the
optimization pass. CPU state, RGB pixels, and PCM output matched before and
after that optimization. This compares two points within this development
work, not a benchmark against the published v1.0.3 package. It excludes desktop
scaling and physical audio playback and does not guarantee sustained 60 FPS on
every computer or scene. See the [performance report](../performance/performance-report.md).

## Upgrading From v1.0.3

### Desktop And Standalone Users

Enable the new audio pilot explicitly:

```bash
python nes.py rom/game.nes --audio-pilot
```

The packaged Linux command is:

```bash
./nes-py-linux-x86_64 rom/game.nes --audio-pilot
```

On Windows PowerShell:

```powershell
.\nes-py-windows-x86_64.exe rom\game.nes --audio-pilot
```

Launching without `--audio-pilot` does not create an APU or request an audio
device. Existing ROMs remain local files; none are included with the release.
Press F3 when investigating slow scenes and report both FPS and work timings.

### Python API Users

The experimental core API has breaking changes in this version:

- Enable audio with `NES.from_ines_file(path, audio_sample_rate=44100)`.
- `NES.run_frame()` returns elapsed CPU cycles instead of the former
  `(cycles, pcm)` tuple. Obtain audio separately through `nes.apu.drain_samples()`
  and consume it regularly.
- The former `max_instructions` argument to `run_frame()` is removed. Use
  `NES.run(instruction_count)` when a fixed instruction count is required.
- The former whole-frame `render=False` path is superseded by scanline timing;
  `NES.run_frame()` and `PPU.step()` no longer accept that argument.
- The channel objects expose hardware state rather than the old floating-point
  oscillator helper API. Use APU register writes, cycle advancement, and PCM
  draining for integration.
- `framebuffer_bytes` remains an alias for the reusable RGB buffer, and
  `render_sprites()` remains a snapshot helper. Write PPU registers for scrolling
  rather than relying on the former `background_dirty` flag.

For example:

```python
from nes_py import NES

nes = NES.from_ines_file("rom/game.nes", audio_sample_rate=44100)
assert nes.apu is not None
cpu_cycles = nes.run_frame()
pcm = nes.apu.drain_samples()
```

See the [APU migration guide](../apu/pilot.md#migration-from-the-earlier-prototype)
for the model and output differences.

## Validation

Release preparation uses generated-ROM tests, numerical audio checks, dummy
SDL playback/presentation tests, linting, package builds, and CLI smoke checks:

```bash
python -m pytest
python -m ruff check .
python -m build
python nes.py --version
python -m nes_py --version
python scripts/build_standalone.py --name nes-py-linux-x86_64
dist/standalone/nes-py-linux-x86_64 --help
dist/standalone/nes-py-linux-x86_64 --version
```

Local preparation on Linux with Python 3.14.4 passed all **359 tests**, both
from the checkout and from the extracted source distribution. Ruff 0.17.5
passed, both Python distributions built, and the Linux standalone passed
help/version checks and a generated-ROM CPU smoke test. Its desktop/audio loop
also started successfully with dummy SDL video and audio drivers. Archive
inspection confirmed that the guides and source helpers are present and that
proprietary ROMs and generated game captures are absent.

The PR checks run tests on Python 3.11 across Linux, Windows, and macOS and build
the Python distributions. Formal publication additionally builds and verifies
the Linux and Windows standalone executables. Physical-device listening and
game compatibility remain manual checks; generated tests cannot establish them.

## Known Limitations

- CPU execution and register writes are instruction-granular. Exact interrupt
  collision timing and OAM/DMC bus arbitration are incomplete.
- The PPU uses scanline snapshots. Mid-scanline effects, color emphasis,
  odd-frame dot skipping, and the hardware sprite-overflow bug are not emulated.
- The reported underwater graphics-alignment issue is **not confirmed fixed**.
  Better throughput does not by itself establish correct raster timing.
- Audio remains an NTSC pilot. Band-limited resampling, full analog filters,
  audio-device clock feedback, PAL timing, and expansion audio are pending.
- Scenes can still exceed the host's frame budget. Device scheduling and slow
  emulation can cause audio underruns even with bounded queues.
- Mapper coverage remains limited to basic NROM/MMC1/UxROM behavior. NES 2.0
  loading supports only the documented subset of submappers and memory layouts.
  Unofficial CPU opcodes, save states, and battery-backed saves are absent.
